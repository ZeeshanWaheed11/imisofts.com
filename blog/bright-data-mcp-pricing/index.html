Bright Data MCP Pricing: What 5,000 Free Requests Cover

Short answer. The Bright Data MCP server costs nothing for the first 5,000 requests a month and then $1.50 per 1,000 requests on pay as you go, with its browser tools billed at $8 per GB of traffic. The catch sits in Bright Data's own documentation: those 5,000 are not a separate MCP allowance. They are your account's single free pool of 5,000 credits, shared with Bright Data's other scraping APIs and with everyone on a team account, renewed on the 1st with no rollover, and the browser tools draw 5 credits per MB from it. Past the limit, an account with no funds gets errors instead of a bill, and Bright Data's MCP FAQ says you continue by creating a new Web Unlocker zone. We earn a commission from the Bright Data and Apify links on this page, and from no other vendor named here.

Bright Data's figures were read on its MCP pricing page (last modified 1 September 2026), its free-tier and MCP documentation, and the MCP server's README and source code on GitHub, all on 7 October 2026. ZenRows, Firecrawl, Apify and Oxylabs were read on their own pricing pages and docs the same day. Plan rates assume the whole allowance is used. We did not test success rates or speed on any of them.

The free tier is one shared pool, not an MCP grant

The MCP pricing page shows a free tier of 5K requests, and the server's README promises 5,000 free requests a month with no credit card. The documentation is more precise. Its MCP FAQ says the free tier "is not a separate grant" but the account's single shared pool of 5,000 credits, and its free-tier page lists who else draws on that pool: the Web Unlocker API, SERP API, Web Scraper API, Scraper Studio and Browser API. The MCP draws on it because, in Bright Data's words, the MCP server runs on the Web Unlocker API. Bright Data values the pool at about $7.50 a month. Four consequences follow from its own rules:

  • Other products spend it. Usage is deducted from the same pool "regardless of which product made the call", so a scraper running on the same account eats the credits your agent was counting on.
  • Your team shares it. Five developers on one team account average 1,000 requests each a month, about 32 a day.
  • It is for new accounts. Accounts on custom pay-as-you-go pricing or a pre-commit plan are not eligible, and upgrading to a pre-commit plan stops the monthly free credits.
  • It is rate limited until you fund it. Unfunded free-tier accounts are capped at 1,000 requests a minute across the SERP API, Web Unlocker API and proxies.

On a single agent with nothing else on the account, 5,000 requests average 161 a day over a 31-day month. The Free Tier Credits section of the billing overview shows what is left, and the server's session_stats tool counts the requests made in the current session. Open a free Bright Data account and check that counter before you plan a long run.

What one request buys, tool by tool

Only five tools load by default: search_engine, search_engine_batch, scrape_as_markdown, scrape_batch and discover. The README counts 69 tools in all, added in groups such as ecommerce, social and browser, and notes that fewer tools means less context for your agent to process, which is a cost on your model's tokens rather than on Bright Data's bill. How each kind of tool spends the pool, from Bright Data's docs and the open-source server code:

ToolWhat it spends
search_engine1 request per results page; asking for the next page is another request
scrape_as_markdown1 request per page, with unblocking handled on Bright Data's side
search_engine_batch, scrape_batch1 request per query or URL; the code caps a batch at 5, though the README says 10
extract1 scrape, then MCP sampling, which hands the JSON step to your own client's model and its tokens
web_data_* (structured data)1 credit per record delivered, so a call that returns 100 reviews spends 100
scraping_browser_* (13 tools)5 credits per MB of traffic on the free pool, $8 per GB on pay as you go
discoverCalls a separate Discover endpoint that neither the pricing page nor the README prices

So a research task of one search and four page reads costs 5 requests: the free pool covers 1,000 such tasks a month, and pay as you go then charges $7.50 per 1,000 tasks. A task that reads ten known URLs costs 10 requests, which is 500 tasks free and $15 per 1,000 after that. The units drift a little across Bright Data's own pages: the pricing card says "1K requests", the README "1K results" and the Scale plans count "results included". The docs settle it for the scraping APIs: one credit is one request, or one record from the Web Scraper API.

Browser tools are billed by the megabyte

The 13 browser tools are priced by traffic, not by page: $8 per GB on pay as you go, $6 per GB on the Scale plans, and 5 credits per MB on the free pool, so the whole 5,000-credit pool buys about 1 GB of browser traffic a month. At $8 per GB a megabyte costs $0.008, which means a browser page load costs more than a $1.50-per-1,000 scrape once it moves more than about 0.19 MB.

Bright Data's README points agents to scrape_as_markdown for any known URL and to the browser tools only when a page needs a click, typing, a scroll or a login, which is also the cheaper habit.

What happens at request 5,001

Bright Data describes this moment in three places, and they are not identical. The free-tier documentation says an account with funds moves to its pre-paid balance at pay-as-you-go rates with no interruption, while an account without funds gets errors and a prompt to add funds; adding a card is only a verification step, so an unfunded account cannot run up a bill. The MCP FAQ is stricter: past 5,000, requests start failing, and to continue you create a new Web Unlocker zone in the control panel, point the MCP at it (an unlocker parameter on the remote URL, or WEB_UNLOCKER_ZONE when self-hosted) and restart your MCP client. The open-source server goes furthest: when it receives Bright Data's usage-limit error on its default zone, it tells the agent to stop the current task immediately and walk you through those same steps.

In practice, an agent that hits the limit halfway through a long job stops halfway through it. If the job matters, deposit funds and set up your own Unlocker zone before the run, not during it. A self-hosted server also accepts a RATE_LIMIT setting such as 100/1h, but it counts tool calls, not requests, so a five-URL batch passes as one call and spends five requests. For spend control, Bright Data's billing settings offer balance alerts and the README mentions a spend cap in the control panel; auto-recharge, if you enable it, refills the balance and removes the hard stop.

Two things in that table work against the vendors that pay us. At around $100 a month of spend, Bright Data's $1.50 and Apify's $1.50 are the highest rates for an ordinary page: ZenRows Launch charges $0.28, Oxylabs Basic $0.90 and Firecrawl Standard $0.99, and Firecrawl's single credit includes its enhanced proxies. Where Bright Data's flat rate helps is the difficult page: its README says bot detection, CAPTCHA solving and proxy rotation are handled on every request at the one price, while ZenRows charges up to 25 credits for a page that needs JavaScript and premium proxies.

Pay as you go or a plan: the break-even points

Pay as you go has no monthly fee, so at low volume it beats every plan; the useful question is where it stops. Counting Bright Data's 5,000 free requests first:

  • Against ZenRows Build at $19: Bright Data's pay as you go reaches $19 at about 17,700 requests a month. Build's 45,000 credits cover 45,000 standard pages, but only 1,800 that need JavaScript and premium proxies.
  • Against ZenRows Launch at $69: it reaches $69 at 51,000 requests. Launch's credits stretch to 250,000 standard pages but only 10,000 pages that need JavaScript and premium proxies, so the mix of your pages decides which side wins.
  • Against Firecrawl Standard at $99: it reaches $99 at 71,000 requests a month.
  • Against Bright Data's own Scale plan at $499: pay as you go reaches $499 at about 337,700 requests, and moving to Scale ends the free monthly credits.

Above those volumes the plans are cheaper per page, for pages they can fetch at their base credit cost and as long as you stay inside the allowance. Firecrawl's Standard top-ups cost $2.50 per 1,000, more than Bright Data's $1.50.

Which MCP setup to start with

  • An agent that reads a few hundred protected pages a month: Bright Data's free tier, on an account where nothing else spends the pool.
  • From about 18,000 ordinary pages a month: usually a plan. Against Bright Data's pay as you go, ZenRows Build wins from about 17,700 standard pages up to its 45,000 credits, ZenRows Launch from 51,000 and Firecrawl Standard from 71,000. Run 200 of your real URLs through each first, because ZenRows' bill depends on how many pages need JavaScript or premium proxies.
  • Site-specific scrapers the agent can call by name: Apify's MCP server, which searches and runs Store Actors, each with its own price. Its Web Fetch costs the same $1.50 per 1,000 as Bright Data on the Free and Starter plans.
  • Browser-heavy work: budget per megabyte or per minute, not per page. Bright Data bills browser traffic by the gigabyte and ZenRows bills browser sessions at 5 credits a minute.

Bright Data's MCP can also send prompts to ChatGPT, Grok and Perplexity and return their answers as structured data, which its README calls the feedback loop for Generative Engine Optimization. That measuring step is half of AI search optimization; the other half is changing what those assistants find when they look you up.
